## 2. 与架构目标的差异

4+1 文档描述目标架构。首版根据本机环境采用以下明确收敛，不能将未实现能力当作已交付：

| 目标架构 | 当前实现 | 原因 / 后续工作 |
| --- | --- | --- |
| PostgreSQL + pgvector | SQLAlchemy 支持 SQLite/PostgreSQL；默认 SQLite；无向量索引 | 本机无 PostgreSQL 服务；先完成检索归档闭环。需另行验证 PostgreSQL 和嵌入检索 |
| 多层包目录 | 按职责拆分为九个后端模块 | 保持首版可维护规模；模块扩大后再拆子包 |
| PaperVersion / Publication / Venue 独立表 | Paper 元数据 + Document + Run 处理快照 | 独立论文出版版本归并尚未实现，不依据近似标题冒进合并 |
| Claim / ExperimentFinding 独立对象 | 技术描述 + 逐字原文证据 | 尚未提供实验数值对比或独立实验表 |
| StepRun 与任意步骤恢复 | Job 阶段、文档检查点、成功 Run 检查点、发现阶段检查点 | 进程恢复可能重复未保存的模型调用；不承诺恰好一次 |
| 索引 outbox | 关系查询直接读取已提交知识 | 当前无独立索引，无需制造空 outbox；引入向量检索时补充 |
| 多任务并发 Worker | 单 Worker 串行任务、独立心跳线程与解析子进程 | 先保证成本与数据可控；第二 Worker 会被文件锁阻止 |
| 分类树变更后批量重分类 | 接受节点建议并分类原条目；可逐篇重新分析 | 全库重分类和节点移动/合并尚未实现 |
| 完整长文统一综合 | 分批读取与证据提取、保留各批技术 | 上限 32 块，超过范围明确提示；后续增加层次汇总与跨批合并 |

- 主题：cache compression。

- 保存论文 1 篇、文档 1 份，阅读完整度 fulltext。
- 模型请求 0 次；未配置模型时任务为 partial，原因明确为 model_not_configured。

这证明检索、下载、解析与持久化链路可运行，不证明该论文与目标方向的最终学术相关性，也不代表真实模型提取已经验证。

## 5. 用户接入步骤

1. 打开本地工作台，查看知识库、搜索与导入页面。
2. 在根目录 `.env` 配置 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY，重启 API 与 Worker。
3. 导入代表性论文或发起主题搜索。
4. 在任务中心核对阅读范围、模型调用次数、原文证据和分类结果。

真实模型质量评估需要代表性论文与具体模型配置；当前未读取或猜测任何用户凭证。
