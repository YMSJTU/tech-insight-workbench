# 模块二：技术知识库详细设计

日期：2026-10-24。范围：单用户、本地知识库；模块三不实现。

## 1. 实现边界与架构决策

采用 FastAPI、SQLAlchemy、独立 Worker 与 React。模型调用不直连服务商 HTTP API，而是由 Worker 启动本机 ACP agent（默认 `opencode acp`），在 agent 会话中完成阅读与提取；模型与凭证由 agent 管理。为当前无数据库服务的 Windows 环境提供 SQLite WAL 默认配置；DATABASE_URL 可切换 PostgreSQL。SQLite 仅支持一个 Worker，数据库任务通过条件更新领取；PostgreSQL 也保留租约校验。首版使用关系筛选与文本查询，语义向量检索留作明确的后续增量，不将关键词匹配称作语义检索。数据库 schema 使用版本标记；后续结构升级必须提供迁移。

文件保存在 data/files，数据库默认 data/workbench.db。API 只提交任务，不执行模型长调用。Worker 默认串行，独立进程运行；任务状态持久化，启动后可恢复过期租约。前端由 API 提供构建产物。

## 2. 数据模型

所有 ID 使用 UUID 字符串，时间使用 UTC ISO 字符串。JSON 字段保存有版本的处理产物，适合第一版迭代；需要关联查询的身份、分类、任务与证据独立保存。

| 表 | 关键字段与约束 |
| --- | --- |
| schema_versions | version 主键，初版为 1 |
| papers | id；identity 唯一；title；doi；authors JSON；year；venue；url；abstract；reading_level；coverage_note；current_run_id；created_at |
| documents | id；paper_id；sha256；storage_name；kind；pages JSON；同一论文与哈希唯一 |
| runs | id；paper_id；document_id；model；prompt_version；taxonomy_version；status；summary；limitations JSON；created_at |
| techniques | id；run_id；name；mechanism；problem；conditions；limitations；claims JSON（证据引用） |
| evidence | id；run_id；block_id；page；quote；document_id |
| classifications | id；paper_id；technique_id 可空；node_id；run_id；confidence；reason |
| taxonomy | id；dimension=technology/problem；parent_id；name；description；version；同父同名同域唯一 |
| proposals | id；paper_id；run_id；dimension；parent_id；name；reason；status；resolved_node_id |
| jobs | id；kind；parent_id；status；stage；payload/result JSON；error；attempts；lease_token；lease_until；cancel_requested；created_at/updated_at |

一个 run 是一次处理快照。正文或摘要改变产生新 run；成功校验后事务写入技术、证据、分类，并切换 papers.current_run_id。旧 run 不删除，新 run 失败不影响已有可用结果。技术条目按论文处理记录独立生成，不自动合并跨论文同名技术。

论文身份优先 DOI、arXiv ID，上传文档使用内容哈希；同文档带 DOI 再导入时优先匹配现有 DOI 或哈希。仅标题相似不自动合并。来源域采用 papers.venue/year 的事实元数据，首版不实现复杂发表版本归并；预印本与会议版没有明确同一身份时分别保存。

## 3. 归档流程

1. 接收元数据、DOI、URL、正文或 PDF 上传，校验大小和输入格式。
2. 建立持久化归档任务，返回 HTTP 202 与任务 ID。
3. 解析 DOI/arXiv 元数据；精确去重后创建或丰富论文，不用空值覆盖已有信息。
4. 上传或下载的 PDF 在解析子进程中提取页文本，超时终止；不支持 OCR 时明确提示。
5. 可读全文优先；否则使用摘要；无内容则元数据级部分完成。归档时在 `papers.coverage_note` 写明“全文（PDF N 页）/ 摘要 / 元数据”及降级原因，阅读级别同时保留。
6. 分块生成稳定的块 ID，保存页码及原文。长文分批提取，每批限制输入长度，最多处理配置的块数；截断必须可见。
7. 将块内容、分类树和结构 schema 发送给配置的模型，得到中文总结、技术机制、问题、条件、局限、带块引用的原文证据和分类建议。
8. 校验引用块存在且 quote 是块内原文，分类节点属于对应维度，置信度在 0–1，至少一个技术具有有效证据；有限修复一次。
9. 事务保存处理快照并切换有效版本；没有合适节点时不阻塞归档，创建扩展建议或保持未分类。

无模型配置：保留文献、文档，任务 partial，明确 model_not_configured；不生成模拟技术。可以在配置后重试。调用超时、限流与服务错误有限次重试；无效 JSON 修复一次仍失败则保留错误与文献。

## 4. ACP agent 契约

Worker 通过 stdio 启动 ACP agent，使用 JSON-RPC 换行分帧：

1. `initialize`：协议版本 1，客户端不声明文件系统或终端能力，agent 不能借工具读取本机文件。
2. `session/new`：工作目录为项目根，`mcpServers` 为空；返回 `sessionId` 与 `configOptions`。
3. `session/set_config_option`：配置了 `ACP_MODEL` 时，校验该值在当前模型选项中并切换，切换结果以返回的 `configOptions.currentValue` 为准。
4. `session/prompt`：发送系统约束与用户提示；收集 `agent_message_chunk` 文本，忽略思维链与工具事件；以 `stopReason=end_turn` 结束，记录返回的 usage。
5. 每个提取批次使用独立 session，避免上一批上下文污染；agent 进程在 Worker 内复用，超时或崩溃后重建。

输出结构：summary；techniques 数组，每项包含 name/mechanism/problem/conditions/limitations、evidence[{block_id,quote}]、classifications[{node_id,confidence,reason}]；proposals[{dimension,parent_id,name,reason}]。程序按同一 schema 校验，并检查 quote 是否为引用块内逐字连续子串、分类节点是否属于正式树、置信度是否在 0–1。技术实验数值写入有证据的描述，不单独推断未提供的基线。

每批最多 18000 字符，默认最多 8 批；提示词要求每批最多 4 个技术条目、每个技术 1–2 条证据，以控制单次输出规模。单次 prompt 超时由 `ACP_TIMEOUT` 控制（默认 300 秒）。任务记录 prompt 次数与 agent 返回的 token usage；用户可设置最大 prompt 次数，调用前检查，校验重试也计数。该上限不等同于精确人民币预算。

无可用 agent 时：保留文献、文档，任务 partial，明确 agent_not_configured；不生成模拟技术。agent 返回无效 JSON 或校验失败时有限次修复；仍失败则保留错误与文献。

## 5. API

| 方法与路径 | 输入 / 输出 |
| --- | --- |
| POST /api/archive | title/doi/url/abstract/text/authors/year/venue/max_calls；返回 job |
| POST /api/search | mode（topic/venue）、topic、venue、sources、year_from/year_to、limit、max_calls；返回父任务 |
| POST /api/upload | PDF multipart + 可选 title/doi；返回 job；最大 25 MB |
| GET /api/papers | q/technology/problem/venue/page/page_size；返回 items/total/facets（含 reading_level/coverage_note） |
| GET /api/papers/{id} | 元数据、coverage_note、有效 run、技术、证据、分类、文档与历史摘要 |
| GET /api/documents/{id}/file | 受控返回已注册文件，禁止任意路径 |
| GET /api/taxonomy | 两维节点与当前版本 |
| GET /api/proposals | 待处理及已处理建议 |
| POST /api/proposals/{id}/resolve | action=accept/reject；expected_version；可选修订 name；接受创建或复用节点并给原论文补分类 |
| POST /api/papers/{id}/reprocess | 根据现有原文建立新任务 |
| GET /api/jobs、GET /api/jobs/{id} | 任务、阶段、子任务、错误、用量 |
| POST /api/jobs/{id}/cancel | 取消当前及所属子任务；已完成结果保留 |
| POST /api/jobs/{id}/retry | 克隆失败/部分完成/取消任务，明确新任务 ID |
| GET /api/settings | 返回 ACP agent 命令、模型、就绪状态与 Worker 心跳，不返回凭证 |

HTTP 错误：400 参数/输入错误；404 不存在；409 版本冲突或状态不允许；413 文件过大；422 schema 不符。

## 6. 页面设计

左侧主导航：知识库、论文搜索、导入论文、任务中心、分类管理、运行配置。知识库提供文本搜索与三维筛选，论文卡片显示年份、来源、阅读范围；详情侧栏展示信息范围说明、技术机制、适用条件、局限、分类、逐条原文证据。搜索页支持“按主题 / 按会议或期刊”两种模式，任务详情显示来源解析、发现/入选数量与逐篇 coverage_note。上传与元数据导入成功后可查看任务。分类管理展示两棵树及待处理建议。配置页说明环境变量和启动方式，不在浏览器储存密钥。

## 7. 可靠性与安全

任务租约携带随机 token；后台心跳续租，提交与状态更新校验 token。默认一个 Worker；进程退出后租约过期恢复。取消在步骤与模型调用前检查；HTTP 请求已发送后不能保证即时撤销。归档写入前再次检查取消与租约，避免过期任务切换有效版本。

文档下载仅 HTTPS/HTTP 公网地址，DNS 结果全部检查，重定向逐跳检查；连接固定为已验证 IP，并保留 TLS SNI/Host，以降低 DNS 重绑定风险。ACP agent 是受信任的本机程序，客户端不声明文件系统与终端能力，agent 不能借 ACP 工具读取本机文件。文本材料不得修改系统指令或执行工具。仅绑定回环地址，无 CORS 开放，写请求校验 Origin。日志不记录凭证。

## 8. 验收

自动化测试覆盖去重、有效版本保护、证据原文校验、分类维度校验、摘要降级、无凭证诚实状态、取消、租约恢复、分类版本冲突、三维查询、文件安全、ACP 协议握手、venue 全量发现、OpenAlex 摘要/PDF 解析、信息范围标记与相关性评分校验。使用测试 ACP agent 验证协议与流程，不将测试桩结果冒充真实模型验收。真实 agent 端到端测试需要运行环境提供可用的 ACP agent；本机已用 opencode 执行一轮真实归类（partial），结果见 [ACP 真实归类测试记录](07-ACP真实归类测试记录.md)；双模式搜索见 [双模式搜索测试记录](08-双模式搜索测试记录.md)。
