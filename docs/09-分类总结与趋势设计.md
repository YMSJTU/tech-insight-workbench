# 分类技术总结、发展趋势与检索优化

日期：2026-10-25。基线提交 `282ff84`，其他 Agent 已完成 ACP 接入与双模式搜索，本轮在分支 `feat/category-insights` 增量开发。

## 用户流程

在知识库选择任意技术域/问题域节点（叶节点或上级节点），生成“技术总结”或“发展趋势”。范围包含其所有子分类、遵循人工分类覆盖，可限定年份与最大论文数。没有可读资料时拒绝生成，不依据题名编造技术内容。

报告异步生成，复用任务中心的预算、取消、重试与进度；成功报告永久保存历史版本。内容包含主题分节、结论与引用、趋势时间线、推断标识和局限。点击引用可查看对应论文。报告范围是当前知识库样本，不宣称覆盖整个学术领域。

## 数据与生成

- 提交时冻结输入快照：分类名称/子树、分类版本、论文题录、年份、阅读范围、当前技术总结和证据摘录，或原始摘要/正文摘录。
- 仅元数据论文计入范围统计，但不进入模型材料。按年份排序取有界样本，明确显示省略篇数；未知年份不生成时间线事件。
- 每篇材料有唯一来源 ID；所有段落与时间线项都必须引用快照内来源，程序拒绝未知引用和不匹配的时间线年份。
- 大范围采用分批归纳，再用 ACP 综合分批结果；缺失批次明确标记部分完成，不伪造全覆盖。
- `category_reports` 保存报告、输入快照、模型、任务 ID 和模板版本。重新生成不覆盖旧报告；查看报告时比较当前输入指纹，提示资料或分类变动。
- 所有模型请求只经过 `agents.call → acp_client → opencode acp`，不增加模型 HTTP 直连。

## 论文归纳优化

过滤独立的 References/Bibliography/参考文献节，保留定位；分批输出允许空技术结果，避免强迫模型从无技术的片段编造。相同规范化技术名合并证据与分类；多批论文可追加一次 ACP 归并，使用条目索引控制分组，原文证据仍由程序合并保留。

## 搜索优化

保留主题与会议模式。修复会议目录截断统计，将“已处理的非论文条目”和“尚未抓取”分开，避免假称全量。主题相关性重排要求完整、唯一的候选评分；可设置最低相关性阈值，未评分候选不冒充已通过语义筛选。预算不足时保留词法排序并标明阈值未应用。

## ACP 可靠性

保留 OpenCode 的 stdio JSON-RPC 会话方式，过滤非当前 session 的通知；取消设宽限期，超时停止子进程；模型配置不支持切换时明确失败，不静默选择其他模型。
