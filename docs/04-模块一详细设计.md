# 模块一：论文搜索详细设计

日期：2026-10-25。依赖模块二的 ArchiveService，不直接写技术与证据数据。

## 1. 输入与两种模式

POST /api/search 返回持久化父任务，输入字段：

| 字段 | 说明 |
| --- | --- |
| mode | `topic`（按主题）或 `venue`（按会议/期刊），默认 topic |
| topic | 主题，2–500 字，仅 topic 模式必填 |
| venue | 会议或期刊名，仅 venue 模式必填，最长 300 字 |
| sources | topic 模式可用 crossref / arxiv / openalex；venue 模式固定 openalex |
| year_from / year_to | 年份范围，可只填一端 |
| limit | 自动归档上限：topic 1–20，venue 1–200 |
| max_calls | 本次搜索及全部子任务共享的 ACP prompt 上限，0–40 |

两种工作流：

- **topic**：生成英文检索词 → 逐来源检索 → 规范化/去重/年份过滤 → 关键词排序 → 可选 ACP 语义重排 → 入选归档。
- **venue**：解析 OpenAlex 来源 → 抓取该年份范围内的全部 works（最多 500 条）→ 过滤版权页、委员会名单、作者索引等非论文条目 → 按来源顺序入选 → 归档。

## 2. 来源适配器

| 来源 | 接口 | 输出与限制 |
| --- | --- | --- |
| Crossref | GET https://api.crossref.org/works；query.bibliographic、rows、filter | DOI、标题、作者、年份、venue、摘要、来源 URL、可选 PDF 链接 |
| arXiv | GET https://export.arxiv.org/api/query；search_query、max_results | Atom 解析，arXiv ID、标题、作者、摘要、日期、PDF 链接；请求间隔至少 3 秒 |
| OpenAlex | GET https://api.openalex.org/works、/sources | 标题、DOI、作者、年份、来源、摘要（inverted index 还原）、开放获取 PDF、收录总数 |

topic 模式每来源最多抓取 limit×3（最高 60）项；venue 模式使用 `cursor` 分页抓取全量，单次搜索上限 500 条并在结果中标记截断。网络超时与来源异常分别记录，其他来源继续。只保存提供方真实返回的信息。

OpenAlex 来源解析使用 `/sources?search=<名称>`，按名称包含、词项重合、来源类型与作品数排序；返回解析到的来源名、类型、总数及备选来源。若匹配到多个来源，父任务记录警告，用户可在任务详情核对。

## 3. 候选规范化与排序

标准 Candidate：identity/title/doi/arxiv_id/authors/year/venue/url/pdf_url/abstract/source/query/reason。DOI 转小写并去除 URL 前缀；arXiv 去版本后缀；OpenAlex 使用 DOI 或标题/URL 哈希。精确身份相同跨来源合并，保留 provenance 列表。不使用模糊标题自动归并。

topic 模式先按年份硬过滤，再用题名/摘要词项重叠与来源顺序排序，理由明确写“关键词命中 + 来源序号”。若模型可用且根任务还有剩余预算，取前 30 个候选交给 ACP agent 做相关性评分（0–1，附中文理由），按分数重排；预算不足、agent 失败或返回无效时回退纯关键词排序并记录警告。这样可排除“内容缓存/网络缓存”等同名不同领域论文。

venue 模式不计算关键词相关性，按 OpenAlex 返回顺序保留全部论文，理由为“会议/期刊目录收录”。最多 limit 个候选自动归档，完整候选、入选标识、查询词、来源错误、归档子任务 ID 保存在父任务 result 中。

## 4. 与模块二协作和信息范围

每个入选候选调用统一归档接口，parent_id 指向搜索任务。子任务独立持有文献输入，父任务取消只取消自己的子任务。数据库论文身份唯一约束负责去重。

子任务按以下顺序获取内容：

1. 用户上传文件或已有全文：直接解析 PDF。
2. 静态 PDF 候选：OpenAlex 全部 locations、发现记录中的 PDF 链接、arXiv ID 构造 URL。
3. 静态候选失败或为空：Unpaywall（需 `UNPAYWALL_EMAIL`）与 OpenAlex DOI 回查补充候选。
4. 每个候选下载前检查公网地址、content-type 和 `%PDF-` 文件头；429/5xx 退避重试，403/404/非 PDF/超限分别分类。每篇最多尝试 `PDF_MAX_CANDIDATES` 个候选。
5. 无全文或全部下载/解析失败：使用摘要，阅读级别 `abstract`。
6. 连摘要也没有：只保存元数据，阅读级别 `metadata`，任务 partial。

每次候选尝试写入 `download_attempts`（URL、来源、状态码、content-type、字节数、错误分类、耗时）。任务 result 保存候选数、尝试列表、成功标记和错误分类，父任务聚合出 PDF 候选覆盖率、下载尝试成功率与全文产出率。

归档时写入 `papers.coverage_note`：

- `全文：已解析 PDF（N 页，图表 M 处）` 或 `全文：已保存正文`
- `摘要：未获取到可下载全文，仅归档摘要`
- `元数据：未获取到摘要或全文`

PDF 解析使用 PyMuPDF，生成逐页 Markdown（正文、GFM 表格、图片/版面链接），整篇存入 `documents.markdown`；ACP 分块直接读取 Markdown，证据校验也基于同一 Markdown 块。表格结构化行/HTML、嵌入图片和含图表页面的版面渲染同时保留，资源写入 `data/files/<pdf>.assets/`，论文详情可查看。`coverage_note` 与 `reading_level` 一起展示在论文详情和逐篇归档结果中。摘要级归档可以是 succeeded；全文下载失败会记录原因并降级，不隐藏缺失。批量入库可把 max_calls 设为 0，只抓取和保存文献，不执行 AI 提取；子任务标记 partial 并记录 `model_budget_exhausted`。

## 5. 预算与父任务状态

max_calls 是整次搜索的 ACP prompt 上限，父任务及所有子任务共享。查询规划、相关性重排、每批技术提取都通过数据库条件更新预留次数；失败重试也计数。任务 result 汇总 tokens（agent 未返回则不推算）。

父任务发现结束后进入 waiting，释放 Worker。Worker 汇总子任务终态：全部成功且无警告为 succeeded；有成果但覆盖受损为 partial；venue 解析失败或全部来源失败为 failed；来源成功但零命中为 succeeded；取消为 cancelled。

## 6. 页面与异常

搜索页提供“按主题 / 按会议或期刊”切换、年份范围、来源、归档数和 ACP prompt 上限。主题模式显示主题输入与来源复选；会议模式显示名称输入并说明会抓取该范围全部论文。提交后跳转任务中心。

任务详情显示模式、来源解析结果、收录总数、发现/入选数量、覆盖率、查询词、相关性重排模式、下载/归档统计、逐篇归档状态与 `coverage_note`。论文详情显示信息范围说明和原文版面/图表缩略图。外部调用失败显示可操作错误，不展示空白成功。
