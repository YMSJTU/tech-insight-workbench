## 5. 发现的问题

1. **证据校验对 PDF 版面过严（已修复）**：首轮 7 批中有 6 批因换行/连字符差异失败。改为 NFKC + 去软连字符 + 合并断行 + 折叠空白后，第二轮降为 1 批失败。剩余失败批次（第 6 批，b21–b24）的 quote 跳过了中间的图注文本，不是连续片段；校验拒绝是正确行为，需要模型改为选择单句证据。
2. **ACP 会话生命周期（已修复）**：opencode 在 `session/close` 后会结束 ACP server，后续批次写入失败；现改为进程内复用、每批新建 session、不逐批 close。
3. **opencode 工作区快照开销（已调整）**：默认会在每个 session 对包含 `.venv`、`node_modules` 的工作区做 git 快照；在隔离配置中设置 `"snapshot": false` 后单批耗时从约 5 分钟降到约 2 分钟。
4. **跨批语义重复（未修复）**：24 条技术中存在 3 个 Prophet 框架变体、2 条插入策略、2 条替换策略、2 条容量调整、2 条提示注入；名称不同，精确去重无法合并，属于已记录的“跨批语义合并”缺口。
5. **参考文献被当成技术（未修复）**：最后一批是第 13–14 页参考文献，模型按题名提取了 DSPatch、DSDP、Berti、CLIP 四条，并明确标注“仅据题名”。需要在分块阶段识别并跳过参考文献/致谢。
6. **耗时**：9 次 prompt 约 15 分钟；单批约 2 分钟。长文全流程仍偏慢，但已可用于人工验收。

## 6. 结论

- ACP 接入路径真实可用：模型调用由 opencode 会话完成，项目侧没有直连模型 HTTP。
- 本轮的归类主判断正确，证据可回溯；主要缺口不在分类模型，而在跨批合并、参考文献过滤和图注/表格造成的证据不连续。
- 下一轮优先级：图注/表格旁的证据选择 → 参考文献过滤 → 跨批技术合并（按名称 + 机制归一）→ 可选的分类置信度阈值。
