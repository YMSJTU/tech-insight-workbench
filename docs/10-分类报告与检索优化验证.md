# 分类报告与检索优化验证

日期：2026-10-25。开发分支 `feat/category-insights`，基于 `282ff84`，完整保留其他 Agent 的 ACP 接入、来源范围标记和双模式搜索提交。

## 实现

- 任意技术域/问题域节点均可生成技术总结或发展趋势，含全部后代分类并尊重论文人工分类。
- 生成前冻结资料快照，可限定年份、论文上限与 ACP 调用次数；仅题录不进入模型材料。
- 报告包含分节结论、论文引用、时间线、推断标记与样本局限，保存历史，支持 Markdown 导出和资料变化提示。
- 所有生成均走 `agents.call → ACP stdio JSON-RPC → opencode acp`，复用现有 agent 配置。
- 单篇论文跳过 References / Bibliography / 参考文献节；同名技术先合并证据与分类，跨批次在预算允许时再用 ACP 归并并形成整篇总结。
- 主题检索支持相关性阈值，默认 0.45；只对完整 ACP 评分的前 30 个候选应用，未评分项不冒充已通过筛选。无可用 ACP 预算时仍可使用明确标记的词法排序。
- 修复 OpenAlex 目录截断的统计：不再把未抓取论文计为过滤项，部分抓取明确提示。
- ACP 忽略其他 session 的通知，显式模型选择不能静默回退，取消有超时宽限，观察到工具调用即停止研究会话。停止工作台时清理其拥有的 ACP 子进程。

## 真实 OpenCode ACP 验证

脚本：`python -m scripts.verify_category_reports`。

使用当前知识库 Cache 预取方向的 3 篇可读论文，冻结为隔离 SQLite 输入快照；模型 `arkchat/doubao-seed-2.1-pro`，通过现有 OpenCode ACP provider 配置调用。未修改正式知识库中的论文或分类。

| 类型 | 状态 | ACP prompt | agent 返回 token | 分节 | 引用来源 |
| --- | --- | --- | --- | --- | --- |
| 技术总结 | succeeded | 1 | 13,965 | 5 | S001 / S002 / S003 |
| 发展趋势 | succeeded | 1 | 12,757 | 5 | S001 / S002 / S003 |

总结含 20 条结论，其中 4 条标为推断；趋势含 20 条结论，其中 8 条标为推断。全部来源 ID 校验通过，时间线年份与所引论文元数据匹配。

现有样本中只有一个已知发表年份（2026），因此趋势报告明确显示“无法验证时间演变，未来方向仅为待验证推断”。这证明模型调用、范围控制与报告交付链路可用，不表示已经获得跨年份趋势证据，也不等于人工完成学术正确性评审。

隔离验证结果与原始报告保存在本机忽略目录 `data/validation/category-acp-check-rv0004x1/`，不提交到 Git。

## 使用

知识库左侧分类节点旁点击报告图标，或直接在“技术总结与发展趋势”卡片选择分类；设定范围后生成报告。任务中心可跟踪进度和打开结果，卡片下方保留历史版本。每条引用可打开对应论文。

归纳基于已保存总结、证据摘录、摘要或有界正文摘录，不重新阅读全文。超出论文上限时跨年份采样，超出调用预算时保留明确的部分完成结果。生成后的分类或文献变化会触发报告过期提示，旧报告不会自动覆盖。
