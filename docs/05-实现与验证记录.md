## 2. 与架构目标的差异

4+1 文档描述目标架构。首版根据本机环境采用以下明确收敛，不能将未实现能力当作已交付：

| 目标架构 | 当前实现 | 原因 / 后续工作 |
| --- | --- | --- |
| PostgreSQL + pgvector | SQLAlchemy 支持 SQLite/PostgreSQL；默认 SQLite；无向量索引 | 本机无 PostgreSQL 服务；先完成检索归档闭环。关键词召回后用 ACP 语义重排，需另行验证 PostgreSQL 和嵌入检索 |
| 多层包目录 | 按职责拆分为九个后端模块 | 保持首版可维护规模；模块扩大后再拆子包 |
| PaperVersion / Publication / Venue 独立表 | Paper 元数据 + Document + Run 处理快照 | 独立论文出版版本归并尚未实现，不依据近似标题冒进合并 |
| Claim / ExperimentFinding 独立对象 | 技术描述 + 逐字原文证据 | 尚未提供实验数值对比或独立实验表 |
| StepRun 与任意步骤恢复 | Job 阶段、文档检查点、成功 Run 检查点、发现阶段检查点 | 进程恢复可能重复未保存的模型调用；不承诺恰好一次 |
| 索引 outbox | 关系查询直接读取已提交知识 | 当前无独立索引，无需制造空 outbox；引入向量检索时补充 |
| schema 迁移框架 | `init_db` 对 `papers.coverage_note` 执行幂等 ALTER，并处理并发启动 | 完整迁移版本管理仍未实现；后续结构化变更需补迁移脚本 |
| 多任务并发 Worker | 单 Worker 串行任务、独立心跳线程与解析子进程 | 先保证成本与数据可控；第二 Worker 会被文件锁阻止 |
| 分类树变更后批量重分类 | 接受节点建议并分类原条目；可逐篇重新分析 | 全库重分类和节点移动/合并尚未实现 |
| 统一模型网关 / 直连 Chat Completions | Worker 启动本机 ACP agent（opencode），每批独立 session | 模型与凭证由 agent 管理；只支持本机 agent，单 prompt 串行 |
| 完整长文统一综合 | 分批读取与证据提取、保留各批技术 | 上限 32 块，超过范围明确提示；后续增加层次汇总与跨批合并 |

### 4.1 ACP 真实归类测试

使用 opencode 2.1.2 作为 ACP agent、`arkchat/doubao-seed-2.1-pro` 模型，对 *Profile-Guided Temporal Prefetching*（14 页、27 个文本块、7 批）执行真实归档：

- Job `4b934a18-49db-4400-8f93-e4019d988647`，Run `29088d41-30a6-4a90-a657-4c85d4908d61`。
- 状态 partial：6/7 批成功；9 次 ACP prompt，143,643 token。
- 产出 24 条技术、41 条原文证据、39 条分类关联、6 条分类建议。
- 分类以 Cache 预取（20）和访存系统优化（9）为主，替换策略关联 Cache 替换，CLIP 关联带宽利用；核心判断符合论文内容。
- 遗留：1 批证据跳过图注文本、3 条剖析技术未分类、4 条参考文献题名被当作技术、跨批语义重复。

详细结果与问题见 [ACP 真实归类测试记录](07-ACP真实归类测试记录.md)。

### 4.2 双模式搜索测试

**会议/期刊模式**：搜索 `HPCA` 2024 年，OpenAlex 返回 93 条，其中 11 条为版权页/委员会/作者索引/Sponsors 等非论文条目，过滤后 82 篇全部入库；19 篇成功下载并解析 PDF，63 篇仅归档摘要，0 篇只剩元数据。模型调用 0 次（max_calls=0），82 个子任务因未执行 AI 提取标为 partial。

## 5. 用户接入步骤

1. 打开本地工作台，查看知识库、搜索与导入页面。
2. 在根目录 `.env` 配置 ACP_COMMAND、ACP_MODEL（可选），重启 API 与 Worker。
3. 按主题或按会议/期刊发起搜索，或直接导入论文。
4. 在任务中心核对来源解析、ACP prompt 次数、逐篇信息范围、原文证据和分类结果。

真实 agent 质量评估使用代表性论文与具体模型配置；当前未读取或猜测任何用户凭证。
