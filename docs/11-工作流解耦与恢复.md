# 工作流解耦与恢复（第一阶段）

本次以分类总结、趋势报告为迁移样板，保留 HTTP 接口和前端操作方式。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| insights.py | 报告步骤组合、提示词、结构与引用校验，不直接操作 ORM |
| report_repository.py | 分类材料查询、快照、报告读写及原子提交 |
| execution.py | 步骤执行、版本与输入指纹、结果复用；可注入存储实现 |
| step_repository.py | 步骤结果持久化，在读取和写入时检查取消与租约 |
| model_gateway.py | 调用 OpenCode ACP，不依赖任务表；通过 CallContext 注入执行策略 |
| agents.py | 保持既有调用接口，JobCallContext 适配预算、取消和用量记录 |

数据库事务不跨越模型调用。报告及其任务结果仍在同一事务内保存。

## 恢复规则

新增 workflow_steps 表，保存成功步骤的输出。每个步骤按任务、步骤名称和输入指纹唯一标识；指纹包含输入、模型标识和工作流/提示词版本。

Worker 重新领取同一任务时复用已完成步骤。用户重试报告时，在新任务创建事务中复制已完成步骤；仅完全匹配的输入和版本可以复用。新的独立生成任务不共享缓存。重试任务有新的调用预算，历史任务保留原用量。

失败批次不写入成功结果。取消或旧租约不能读取复用结果或提交新结果。批次的结构和引用校验通过后才保存；综合步骤也可复用。添加步骤或调整提示词后，应更新 REPORT_VERSION，防止复用旧语义结果。

若进程在模型返回与步骤提交之间崩溃，该调用仍可能重做；本实现不承诺外部模型调用恰好执行一次。运行中的模型提供方配置不应被直接修改；相同模型名背后的服务变化不会被自动识别。

## 验证与边界

63 项后端测试通过，新增覆盖：部分失败后的批次复用、输入/模型/版本变化失效、取消写入、失效租约，以及缺失引用、虚构引用、错误观察类型和错误年份的拒绝。

这些是确定性的证据约束回归测试，不等于语义正确性评测或人工标注论文基准。下一阶段仍需要真实论文金标准及抽取准确性评估。

当前仅报告流程具备步骤恢复。搜索和论文归档仍保留旧编排实现，但共同使用独立 ACP 网关。尚未引入通用 DAG、步骤运行历史、可视化编排或完整数据库迁移框架；新增表使用现有初始化机制创建，不改写旧论文数据。
